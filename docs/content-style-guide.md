# Knowledge Content Style Guide

Write for a beginner who is worried about making a problem worse. Start with what the reader will learn, use short active sentences, define technical terms on first use, and prefer numbered steps only when order matters.

State risk before an action that could remove data, change security settings, open a device, or require an administrator password. Tell readers when to stop and contact the device maker or a qualified repair service. Never present uncertain advice as a guarantee.

Use plain text in article bodies. The public renderer escapes all stored content and adds line breaks; editorial HTML, scripts, embeds, and inline event handlers are not supported. Link only to HTTPS official sources and describe each link instead of using "click here".

Published content needs a category, type, summary, source where applicable, and a visible review date. Review security and error-code content at least every 90 days; review other content when an operating-system or vendor change affects it. Draft, review, and archived content are never public.
